## 短介绍

HomeDatabase 希望让每个家庭拥有自己的 AI 财务副驾。当前版本已实现自托管账本、手机与桌面界面、账单导入复核、家庭分摊与报表，并提供可选 AI 账单识别。项目以可核对的财务记录为基础，规划自然语言问账、现金流预测与生活目标推演，让散落的账单逐步变成有依据、可行动的家庭财务记忆。

## 完整项目介绍

家庭里的钱，往往分散在不同人的银行卡、支付软件和一张张截图里。我们能够查到每一笔交易，却依然很难回答：“这个月为什么多花了钱？”“年底的计划会不会让现金太紧？”

HomeDatabase 从这个日常问题出发，搭建一套可以自行部署的家庭账本。手机 PWA 负责随手记录，桌面管理台负责集中整理；成员权限、共享账户和分摊确认让家庭协作有清楚的边界。CSV / XLSX 可以直接导入，PDF / 图片可在配置 AI 工作器后提取为结构化候选。每一批候选都需要人工确认后才进入正式账本。

项目的技术重点是把“识别”与“财务事实”接起来。数据库使用整数金额与复式分录，配合账期约束、重复检查和来源记录，让后续分析建立在能够核对的数据上。公开仓库提供完整源码、虚构示例数据库、导入模板和自有数据接入说明，便于复现与扩展。

我们进一步提出“家庭 AI CFO”的产品愿景：让账本可以用自然语言提问，让消费变化附带可追溯的证据，让未来支出以情景对比呈现。自然语言问账、现金流预测和目标推演目前属于规划；它们将沿着已有的权限、账本和 API 基础逐步推进。

HomeDatabase 想做的是一个可以陪伴家庭持续积累的财务记忆系统。今天，它帮助人们把账记清楚；未来，我们希望它帮助家人把计划谈明白、把选择看清楚。

## 三分钟演示脚本

使用独立的演示数据目录，并提前按 [README](../README.md) 启动前后端。下面的主流程只依赖 CSV，可在未配置 AI 的环境中完成。

| 时间 | 展示内容 | 建议讲述 |
| --- | --- | --- |
| 0:00–0:25 | 打开首页和手机入口 | “家庭财务散落在很多地方。我们希望把这些记录，变成一家人可以共同理解的财务记忆。” |
| 0:25–0:50 | 登录演示账号，展示账户与桌面管理台 | “这套系统已经能运行，手机和桌面连接同一套账本；个人与共享账户按权限呈现。” |
| 0:50–1:30 | 上传 `examples/transactions.csv`，查看候选 | “导入之后先复核。日期、金额和分类都可以检查，确认之后才写入。” |
| 1:30–1:55 | 确认入账，查看流水和报表 | “账单从文件变成结构化记录，再形成可核对的统计。” |
| 1:55–2:20 | 展示 AI 工作器架构与配置说明 | “项目也提供可选的图片 / PDF 识别。配置模型后，AI 输出进入同一个候选确认流程。” |
| 2:20–2:50 | 打开 AI 路线图 | “下一步，我们计划让这些记录支持自然语言问账、现金流预测和生活目标推演。这部分是未来路线。” |
| 2:50–3:00 | 展示仓库和数据接入入口 | “从自己的数据开始，把家庭账本逐步变成自己的 AI 财务副驾。” |

## 面向评审的问答

**AI 已经做到了哪一步？**

当前提供可配置的图片 / PDF 识别工作器和结构化候选流程。自然语言问账、预测、主动提醒与情景推演尚未实现，已列入产品路线图。

**项目的差异化方向是什么？**

将家庭成员协作、自托管账本、可复核的 AI 输入与长期财务规划放进同一条产品路线。当前的技术基础让每笔数字可以核对，也为未来的证据式问答提供连接点。

**能接入真实数据吗？**

可以从独立空库开始，设置自己的账号，通过 CSV / XLSX 候选确认导入，或根据 OpenAPI 接入其他系统。公开仓库的数据库与样例均为虚构数据。

**AI 处理的数据会去哪里？**

默认本地启动不调用 AI。启用 OCR 后，待识别页面会交给所配置的模型服务；账本数据库可以自行部署。未来将探索本地模型适配与更细的数据范围控制。

**下一步最值得验证的能力是什么？**

优先验证带来源的自然语言问账：模型理解问题，受控接口查数，确定性代码计算，回答附上记录来源。它能直接检验 AI 是否真正帮助用户理解账本。
